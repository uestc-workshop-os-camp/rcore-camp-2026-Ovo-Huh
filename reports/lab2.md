# rCore 第四章：地址空间与虚拟内存管理

## 1. 本章在做什么

第四章的核心：为每个应用建立独立的虚拟地址空间，并通过页表把虚拟地址映射到物理地址。

整体关系：

```text
用户程序
  ↓ 系统调用 / 异常
内核处理
  ↓
MemorySet（管理地址空间）
  ↓
PageTable（建立地址映射）
  ↓
物理页帧（由 FrameAllocator 分配）
```

主要模块：

| 模块 | 作用 |
|---|---|
| `address.rs` | 地址、页号及转换 |
| `frame_allocator.rs` | 物理页帧分配与回收 |
| `page_table.rs` | 页表和页表项管理 |
| `memory_set.rs` | 管理完整地址空间 |
| `trap/` | 异常处理和上下文切换 |
| `syscall/` | 用户程序请求内核服务 |

## 2. 地址与页号：`address.rs`

四种基本类型：

- `VirtAddr` / `PhysAddr`：虚拟地址 / 物理地址。
- `VirtPageNum` / `PhysPageNum`：虚拟页号 / 物理页号。

页面大小为 4096 字节（4KB），地址可以拆成：

```text
虚拟地址 = 虚拟页号 + 页内偏移
```

常用方法：

| 方法 | 作用 |
|---|---|
| `floor()` | 向下取整，得到所在页号 |
| `ceil()` | 向上取整，得到结束页号 |
| `page_offset()` | 获取页内偏移 |
| `aligned()` | 判断是否页对齐 |

rCore 使用 Sv39 三级页表：

```text
虚拟地址（39位）
| VPN[2] | VPN[1] | VPN[0] | Offset |
|  9位   |  9位   |  9位   |  12位  |
```

每级页表有 512 个表项。`VPNRange` 用左闭右开区间表示一段虚拟页。

## 3. 物理页帧：`frame_allocator.rs`

页帧分配器负责分配和回收物理页面。

- `frame_alloc()`：申请一个物理页帧。
- `FrameTracker`：记录已分配的页帧。
- `Drop`：`FrameTracker` 生命周期结束时自动回收页帧。

因此，区域持有的 `FrameTracker` 被释放后，对应物理页帧也会被回收。

## 4. 页表：`page_table.rs`

页表负责建立虚拟页号 VPN 到物理页号 PPN 的映射。

- `PageTableEntry`：保存物理页号和权限标志。
- `PTEFlags`：包括有效位 `V`、读 `R`、写 `W`、执行 `X`、用户态 `U` 等。
- `map()`：建立映射。
- `unmap()`：解除映射。
- `translate()`：根据虚拟页号查找页表项。
- `token()`：生成页表标识，写入 `satp` 后可启用对应页表。

Sv39 查表时，使用虚拟页号的三级索引逐级查找，最终得到物理页号，再加上页内偏移得到物理地址。

切换页表后使用：

```rust
asm!("sfence.vma");
```

用于刷新地址转换相关缓存，避免继续使用旧映射。

`translated_byte_buffer()` 用于把用户传入的虚拟地址缓冲区转换成内核可访问的物理页缓冲区；缓冲区跨页时需要分段处理。

## 5. 地址空间：`memory_set.rs`

`MemorySet` 表示一个完整的虚拟地址空间，主要包含：

- `page_table`：该地址空间使用的页表。
- `areas`：该地址空间中的多个内存区域。

`MapArea` 表示一段连续虚拟内存，记录页范围、映射类型、权限以及分配的物理页帧。

映射类型：

- `Identical`：虚拟页号与物理页号相同。
- `Framed`：为虚拟页分配新的物理页帧。

权限 `MapPermission`：

- `R`：可读；`W`：可写；`X`：可执行；`U`：用户态可访问。

常见操作：

- `push()`：向地址空间添加区域并建立映射。
- `map_one()`：映射一个页面。
- `unmap_one()`：解除一个页面的映射。
- `copy_data()`：把程序初始数据复制到映射区域。
- `shrink_to()`：缩小区域并释放多余页面。
- `append_to()`：把区域映射到目标页表。

**记住：PageTable 管映射，MemorySet 管整个地址空间。**

## 6. Trap：进入和返回内核

`TrapContext` 保存用户程序的运行现场，主要包括通用寄存器、`sstatus` 和 `sepc`。

```text
用户程序
   ↓ 异常 / ecall
__alltraps：保存上下文，切换内核栈
   ↓
trap_handler：处理异常或系统调用
   ↓
__restore：恢复上下文
   ↓
sret：返回用户态
```

`sscratch` 用于辅助保存和交换用户栈、TrapContext 等信息。

## 7. 第四章主要系统调用

### `sys_get_time`

获取当前时间，并将秒和微秒写入用户提供的 `TimeVal`。用户指针是虚拟地址，内核需要通过地址转换后才能安全访问。

### `sys_trace`

读取或修改用户空间的一个字节。需要检查地址映射和访问权限，不能把用户虚拟地址直接当成物理地址。

### `sys_mmap`

为用户程序申请一段新的内存映射。

参数：`start`（起始地址）、`len`（长度）、`prot`（权限）。

`prot`：1=R，2=W，3=R|W，4=X，5=R|X，6=W|X，7=R|W|X。映射时还要添加 `U` 权限。

主要检查：地址对齐、长度非零、权限合法、地址计算不溢出、不超出用户地址范围、不能与已有区域重叠。成功返回 0，失败返回 -1。

### `sys_munmap`

解除已有映射。当前实现要求起始地址页对齐、长度非零且为页大小的整数倍，并且传入范围要与已有区域完全匹配。

解除时删除页表映射并释放对应物理页帧。成功返回 0，失败返回 -1。

### `sys_sbrk`

调整程序堆的大小：

- 申请内存：堆顶向高地址移动。
- 释放内存：堆顶向低地址移动。
- 成功返回调整前的 break point，失败返回 -1。

释放后的内存不应继续访问，否则可能触发 PageFault。

## 9. 本章记忆重点

1. 虚拟地址通过页表映射到物理地址。
2. `FrameAllocator` 管物理页帧分配，`FrameTracker` 负责自动回收。
3. `PageTable` 管页映射，`MemorySet` 管完整地址空间。
4. Sv39 使用三级页表，虚拟地址由三级索引和页内偏移组成。
5. 用户程序通过系统调用请求内核服务；内核访问用户缓冲区前需要进行地址转换和权限检查。
6. `mmap` 建立映射，`munmap` 解除映射，`sbrk` 调整堆大小。
