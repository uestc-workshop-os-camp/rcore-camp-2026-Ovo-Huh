# 第三章：多道程序与任务切换

## 1. 本章主要内容

第三章主要学习操作系统如何管理多个应用程序，以及如何在多个任务之间切换执行。

多道程序允许多个应用程序交替使用 CPU，提高 CPU 的利用率。

## 2. 核心概念

### 2.1 任务与任务状态

操作系统通过任务控制块（Task Control Block，TCB）管理任务。

任务主要有三种状态：

| 状态 | 含义 |
|---|---|
| Ready | 就绪，等待 CPU |
| Running | 正在运行 |
| Exited | 已经退出 |

任务状态会随着调度发生变化：

- Ready → Running：任务开始执行。
- Running → Ready：任务暂停，等待下次执行。
- Running → Exited：任务执行结束。

### 2.2 任务管理器

`TaskManager` 负责管理任务，内部维护任务列表和当前任务编号。

主要函数：

- `run_first_task()`：启动第一个任务。
- `find_next_task()`：寻找下一个可以执行的任务。
- `run_next_task()`：切换到下一个任务。

### 2.3 上下文切换

每个任务暂停时，都需要保存当前执行状态，以便之后继续运行。

`TaskContext` 保存任务切换需要的寄存器信息。

`__switch` 是汇编实现的上下文切换函数，主要完成：

1. 保存当前任务的上下文。
2. 恢复下一个任务的上下文。
3. 切换到下一个任务继续执行。

### 2.4 中断与异常

`trap/` 负责处理中断和异常。

常见情况：

- 定时器中断：让操作系统有机会进行任务调度。
- 异常：程序执行过程中发生特殊情况。
- 系统调用：应用程序请求操作系统提供服务。

### 2.5 系统调用

应用程序不能直接随意操作内核资源，需要通过系统调用请求内核完成工作。

例如：

- `write`：输出内容。
- `exit`：退出程序。
- `sys_trace`：记录和查询程序行为。

### 2.6 应用程序加载

`loader.rs` 负责将应用程序加载到内存中，并为任务准备用户栈、内核栈以及初始上下文。

## 3. 代码结构

| 文件或目录 | 主要作用 |
|---|---|
| `batch.rs` | 批处理程序执行 |
| `loader.rs` | 加载应用程序 |
| `task/` | 任务管理与上下文切换 |
| `trap/` | 中断和异常处理 |
| `syscall/` | 系统调用 |
| `timer.rs` | 定时器管理 |
| `sync/` | 同步与互斥相关功能 |

## 4. 任务执行流程

1. 加载应用程序。
2. 创建任务并初始化上下文。
3. 启动第一个任务。
4. 任务开始运行。
5. 发生中断、异常或系统调用。
6. 操作系统进行相应处理。
7. 调度下一个任务，继续执行。

## 5. 本章总结

第三章主要理解三个方面：

- **任务管理**：操作系统如何管理多个应用程序。
- **上下文切换**：如何保存和恢复任务的执行状态。
- **中断与系统调用**：应用程序如何与操作系统交互。

本章的核心就是：操作系统通过任务管理器管理多个任务，通过上下文切换实现任务交替执行，通过中断和系统调用与应用程序交互。
